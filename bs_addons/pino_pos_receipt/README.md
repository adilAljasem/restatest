# Pino POS Receipt & Kitchen Ticket Design (Odoo 19)

موديولة تُغيّر تصميم **فاتورة المبيعات** و**إيصال المطبخ (KOT)** في نقطة البيع،
مع إمكانية تشغيل كل تصميم أو إيقافه من إعدادات نقطة البيع.

## محتويات الموديول — ٨ ملفات فقط

```
pino_pos_receipt/
├── __init__.py
├── __manifest__.py
├── pino_models.py                      ← كل كود بايثون في ملف واحد
├── pino_views.xml                      ← كل الشاشات في ملف واحد
├── README.md
└── static/src/
    ├── pino_receipt.css
    ├── pino_receipt.js                 ← كل كود الواجهة في ملف واحد
    ├── pino_order_receipt.xml
    └── pino_kitchen_receipt.xml
```

البنية مسطّحة عن قصد: لا توجد حزم بايثون فرعية، فلا يمكن أن يضيع مجلد
أثناء النسخ أو الرفع إلى المستودع. بعد فك الضغط تأكد أن العدد ٨ ملفات
كما في الشجرة أعلاه.

## التثبيت

1. **احذف أي نسخة قديمة من الموديول أولاً** (المجلد بالكامل)، فالبنية تغيّرت.
2. انسخ مجلد `pino_pos_receipt` داخل مسار الإضافات.
3. تحديث قائمة التطبيقات ← ابحث عن `Pino POS Receipt` ← تثبيت.

المتطلبات: `point_of_sale` و `pos_restaurant`.

## التشغيل

من مكانين، أيهما أسهل لك:

- **نقطة البيع ← التهيئة ← الإعدادات** ← اختر نقطة البيع ← قسم *Bills & Receipts*.
- **نقطة البيع ← Configuration ← Point of Sales** ← افتح نقطة البيع ← تبويب *Configuration*.

| الإعداد | الوظيفة |
|---|---|
| تصميم فاتورة المبيعات المخصص | تشغيل/إيقاف تصميم الفاتورة. عند الإيقاف يعود التصميم الافتراضي فوراً. |
| تصميم إيصال المطبخ المخصص | تشغيل/إيقاف تصميم إيصال المطبخ على طابعات الطلبات. |
| اسم الصنف باللاتينية | إظهار الاسم اللاتيني أسفل الاسم العربي. |
| رمز QR (الزكاة والضريبة) | إظهار صندوق رمز الاستجابة السريعة. |
| الباركود | إظهار باركود Code128 لرقم الفاتورة. |
| العبارة التسويقية / الموقع / عبارة الشكر / عنوان إيصال المطبخ | نصوص حرة تُطبع كما هي. |

بعد أي تغيير: أغلق جلسة نقطة البيع وأعد فتحها مع تحديث قسري للصفحة.

## الأسماء اللاتينية للأصناف

**نقطة البيع ← Products ← الأسماء اللاتينية للأصناف** — قائمة قابلة للتحرير
المباشر لتعبئة الاسم اللاتيني لكل صنف. زر **اقتراح الأسماء اللاتينية** في قائمة
Actions يملأ ما له ترجمة لاتينية جاهزة. إذا بقي الحقل فارغاً لا يُطبع سطر لاتيني.

## من أين تأتي البيانات المطبوعة

| العنصر | المصدر في أودو |
|---|---|
| الشعار | شعار الشركة (أو شعار الإيصال في إعدادات نقطة البيع) |
| سطر الشركة | نص رأس الإيصال `Receipt Header`، وإلا اسم الشركة |
| خدمة العملاء | هاتف الشركة |
| الرقم الضريبي / س.ت | `vat` و `company_registry` |
| رقم الفاتورة | مرجع الطلب `pos_reference` |
| رقم الطلب | `tracking_number` — تُطبع آخر ثلاث خانات فقط (41006 ← 006) |
| نوع الطلب / الطاولة | الـ Preset ورقم الطاولة |
| رمز QR | تطبيق `l10n_sa_pos` المعتمد من هيئة الزكاة والضريبة |
| الباركود | يُولَّد داخل المتصفح (Code128) — يعمل بدون إنترنت |

## ملاحظات فنية

- التصميم الافتراضي لأودو لم يُحذف، بل يُخفى عند تفعيل التصميم المخصص، لذلك
  تبقى الإضافات الأخرى التي ترث قالب الإيصال (مثل `l10n_sa_pos`) تعمل بلا تعارض.
- ملف التنسيق مستثنى من تحويل RTL الذي يطبّقه أودو على الحزم في اللغات العربية،
  لأن التصميم مكتوب أصلاً للاتجاه من اليمين ولا يجوز عكسه مرة ثانية.
- كل الألوان أسود كامل، لأن الرمادي يتحول على الورق الحراري إلى تنقيط باهت.
- جميع المقاسات نسبية (`em` / `%`) لتظهر صحيحة على الشاشة، وفي الطباعة من
  المتصفح، وفي الطباعة الحرارية عبر `ePOS`.
