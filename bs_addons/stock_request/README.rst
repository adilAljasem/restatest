This module was written to allow users to request products that are
frequently stocked by the company, to be transferred to their chosen
location.

Configuration
=============

This module does not require functional settings. Stock requests always use
the main request screen and the internal transfer workflow.

Users should be assigned to Stock Request User, Stock Request Warehouse
Responsible, or Stock Request Manager according to their operational role.

## Group Stock Request / User

- Can see her/his own Stock Requests, and others that she/he's been
  granted permission to follow.
- Can create/update only her/his Stock Requests.

## Group Stock Request / Manager

- Can fully manage all Stock Requests

Usage
=====

Stock Request: ``Request -> Submit -> Accept -> Deliver -> Receive``.

Direct Transfer: ``Direct Transfer -> Confirm -> Deliver -> Receive``.

Both operations create a Delivery from source stock to Transit and a chained
Receipt from Transit to destination stock. The destination warehouse Receiving
Transit Location is used first, with the company Default Internal Transit
Location as fallback. The selected location is stored on the operation so later
configuration changes do not affect existing transfers or backorders.

Known issues / Roadmap
======================

Only cancelled and completed stock requests can be archived.

It is also required to manage the active field logically from requests to
their internal product lines.
